## Kế hoạch trước code

- Dùng schema KycProfile hiện có, mã hóa CCCD và tên bằng AES-256-GCM với key_id, AAD gắn user/field/key. HMAC-SHA256 dùng pepper riêng để bảo đảm unique CCCD. Không log CCCD, tên, OTP hoặc hash.
- OTP Redis TTL, cooldown và giới hạn thử trong Lua atomic. OTP gắn user + challenge và payload KYC. Chỉ một challenge hiện hành mỗi user. Các key cùng user có hash tag để thao tác atomic.
- POST challenge/verify dùng Idempotency-Key. Xác minh thành công tạo profile cùng AuditRecorded Outbox trong transaction, ràng buộc unique DB xử lý đua cùng CCCD. Retry sau lỗi DB phải phục hồi được, secret Redis có TTL.
- GET kyc/me trả verified/kycHash phục vụ giới hạn, internal endpoint user theo X-Internal-Key cho backend. Chỉ profile đã xác minh mới được trả hash. Nội dung KYC không xuất qua API.
- Cấu hình Redis, key ring, active key, HMAC pepper và OTP TTL/attempts/cooldown trong env schema/.env.example. Thư viện Redis dùng ioredis đã có trong repo.
- Test crypto trước, rồi Redis/PostgreSQL thực tế cho OTP sai/hết hạn/replay, uniqueness và ≥50 thao tác cạnh tranh. Delivery cần kiểm thử theo kênh người dùng chọn. Export OpenAPI, README, status, lint/typecheck/unit/integration/concurrency/format/build trước PR.

## Tiếp tục sau lựa chọn kênh OTP — 2026-11-12

- Người dùng chọn email tài khoản và Mailpit local. OTP chỉ gửi tới email đọc từ user ACTIVE trong identity_db.
- Kế hoạch phần tích hợp trước code gồm SMTP adapter Nodemailer, env schema fail-fast khi bật KYC, challenge/verify HTTP và status/internal hash, DB transaction profile cùng AuditRecorded Outbox. SMTP test dùng Mailpit container riêng, dữ liệu tổng hợp.
- Verify gắn challenge với user/email và payload đã mã hóa. Profile đã verified giữ nguyên CCCD, retry cùng CCCD idempotent. Các thay đổi thông tin KYC sau xác minh cần quy trình riêng, trả conflict trong phạm vi này.
- SMTP gửi mã đồng bộ khi tạo challenge, giới hạn timeout. Thất bại delivery trả lỗi và vô hiệu challenge bằng compare challenge ID. Cooldown giữ nguyên để tránh spam retry. Replay cùng Idempotency-Key không gửi lại mail đã gửi.
- OTP đúng có thể phục hồi sau transaction DB thất bại trong TTL. Commit thành công ghi marker consume Redis, và DB ghi nhận kết quả idempotent để replay sau khi Redis hết TTL. Cần xử lý an toàn nếu crash giữa hai hệ thống.
- Bổ sung relay Identity có cờ cấu hình riêng để phát AuditRecorded đã ghi vào Outbox. Relay dùng pool pg riêng và thư viện OutboxRelay, dừng trước khi đóng pool. Test Kafka thật cho audit sau verify, không phụ thuộc provider thật.
