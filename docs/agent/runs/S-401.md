## Kế hoạch trước code

- Thêm migration riêng trong ticket_db cho read-model event/organizer, gates, staff_assignments, liên kết ticket/cổng và receipt idempotency. Composite FK bảo đảm cổng cùng event. Mỗi vé có một cổng, thao tác gắn lần đầu hoặc replay cùng cổng.
- Dựng tenant binding từ EventApproved/EventUpdated/EventCancelled trong hợp đồng hiện hành qua Inbox. Tenant lấy từ organizer_id của sự kiện, xác minh envelope nếu có. Cancellation là terminal, message cũ giữ đúng source version. Event chưa có binding trả EVENT_NOT_READY.
- API Organizer cùng tenant hoặc Admin tạo cổng, phân công/thu hồi Staff và gắn vé. AuditRecorded qua Outbox cùng transaction. Mọi POST dùng UUID Idempotency-Key và chặn cùng key khác payload.
- Staff chỉ list/download cổng được phân công, organizer claim phải khớp event. Kiểm tra assignment trên mọi lần tải và replay. Revocation được tuần tự hóa với download bằng khóa gate row trong transaction.
- Package chỉ gồm ID vé, trạng thái ACTIVE, secret_version và secret hiện hành của đúng event/cổng. Dùng AES-256-GCM cho payload, RSA-OAEP-SHA256 bọc khóa theo public key thiết bị gửi lên. AAD gắn package/event/gate/issued/expires. Khóa riêng ở thiết bị. TTL mặc định 600 giây, env validate 60–1800. WebCrypto giải mã được định dạng ciphertext nối tag 128-bit.
- Lưu response đã mã hóa trong receipt để replay trả cùng package; package quá hạn yêu cầu key mới. Giới hạn số vé mỗi package có cấu hình, vượt giới hạn trả lỗi rõ ràng. PWA/PIN/IndexedDB thuộc V-401, ghi tài liệu giao diện để Vũ tích hợp.
- Test crypto trước bằng WebCrypto, integration PostgreSQL thật cho role/tenant/cổng/thu hồi/TTL/replay/rollback, concurrency ít nhất 50 request. Kiểm tra worker Kafka nhận lifecycle, migration DB rỗng, export OpenAPI, lint/typecheck/unit/integration/concurrency/format/build.
