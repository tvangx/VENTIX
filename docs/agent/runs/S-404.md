## Kế hoạch trước code

- Thêm ticket_freezes trong ticket_db, binding Listing ID/seller/ticket và trạng thái FROZEN/RELEASED. Một binding FROZEN mỗi ticket. Freeze chỉ từ ACTIVE đúng owner. Unfreeze theo đúng Listing ID, có tombstone RELEASED để chặn freeze đến muộn; giữ trạng thái cuối REVOKED/REFUNDED/CHECKED_IN.
- POST /v1/internal/tickets/:ticketId/freeze và /unfreeze dùng X-Internal-Key so sánh constant-time, Idempotency-Key bằng listing_id, body listing_id/seller_id. Response lấy event/original price/owner từ DB Ticket. AuditRecorded Outbox cùng transaction với thay đổi.
- Resale POST /v1/listings dùng QuoteRequest hiện hành, ask_price_vnd number nguyên an toàn. Phép tính cap dùng BigInt và max_percent hiện có, snapshot giá/cap vào listing. Giá gốc lấy từ kết quả freeze, ràng buộc 120% và unique ACTIVE của S-304 được giữ.
- Dùng listing_operations làm intent/receipt bền vững, unique seller/scope/key và fingerprint. Create đi qua PENDING→FROZEN→COMPLETED, có RELEASING→FAILED để bù khi cap/ticket không hợp lệ. Mỗi bước lưu phase trước thao tác bù để retry sau crash. Binding Ticket và Listing ID ổn định qua retry, token JWT giữ trong request.
- Cancel đánh dấu listing CANCELLED và ListingCancelled Outbox trước khi unfreeze, rồi hoàn tất operation. Retry unfreeze theo binding xử lý timeout/response mất mà không mở lại listing hay tác động binding khác. Worker phục hồi operation đang dở với backoff, cờ cấu hình tách khỏi relay/Kafka.
- Consumer TicketRevoked/CheckedIn qua Inbox lưu tombstone terminal và hủy listing ACTIVE qua Outbox cùng transaction. Điều này ngăn listing hồi sinh khi tín hiệu thu hồi đến trước commit tạo listing. TicketRevoked TRANSFERRED được để cho luồng chuyển quyền S-405 xử lý riêng theo source hiện hành.
- GET /v1/listings tìm ACTIVE theo event/cursor và khoảng giá, dùng JWT mặc định của service. API GET me và quote S-304 tiếp tục phục vụ caller hiện hành.
- Thêm workspace event-contracts/outbox-inbox, kafkajs và uuidv7 đã có trong repo. Env schema/.env.example cho INTERNAL_API_KEY, relay/recovery, broker; dùng Ticket URL hiện có và timeout có giới hạn. Endpoint nội bộ fail closed khi thiếu key.
- Test cùng code cho Ticket binding/tombstone/ownership/state, Resale create/cancel/idempotency/cap, HTTP thật giữa hai service và hai DB/user riêng. Kiểm thử lỗi sau freeze/commit, worker phục hồi, Kafka terminal tombstone và >=50 tác vụ cạnh tranh. Migration create-only rồi sửa SQL, chạy từ DB rỗng, lint/typecheck/unit/integration/concurrency/OpenAPI/format/build.
